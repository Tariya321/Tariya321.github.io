## 1. 数据格式
---

数据格式尚未定稿。先按“**存储格式**”“**计算格式**”和“**量化表示**”三个维度建立统一口径；后续确定模型、硬件与推理框架后，再补充实际使用的格式组合。

> [!info] 阅读说明
> - 浮点数的“最小值”容易产生歧义：下表同时列出**最大有限绝对值**、**最小正规格化正数**与**最小非零正数（次正规数）**。
> - 整数的范围是编码本身的范围；量化后真实值范围还取决于 scale 和 zero-point。
> - 表中数值为格式的理论范围，实际硬件、框架和算子可能不支持次正规数或某些低精度类型。

### 1.1. AI 中常见的数据表示

|类别|常见格式|主要用途|关键特性|
|---|---|---|---|
|浮点格式|FP32、FP16、BF16|训练、激活值与高精度计算|可表示连续数值；精度与动态范围取决于指数位、尾数位|
|AI 低精度浮点|TF32、FP8 E4M3FN、FP8 E5M2|Tensor Core 计算、训练与部分推理|仍有指数位，动态范围通常优于同位宽整数；格式和支持范围依赖硬件|
|整数编码|INT8、UINT8、INT4、INT2、INT32|量化权重/激活、输入数据、累加|编码范围固定；通常需要配合 scale / zero-point 还原含义|
|码本 / 块量化|NF4、GGUF 的 Q4_K 等|大模型权重压缩|编码不一定对应等间隔数值；数值范围由块级 scale 或码本共同决定|

### 1.2. 浮点数的位表示

对大多数二进制浮点格式，正规格化数可表示为：

$$
x = (-1)^s \times 2^{e-\mathrm{bias}} \times \left(1+\frac{f}{2^m}\right)
$$

- $s$：符号位（sign），决定正负。
- $e$：指数（exponent），决定动态范围；指数位更多，能表示的数量级跨度更大。
- $f$：尾数 / 小数部分（fraction）；$m$ 为尾数位数。尾数位更多，相邻可表示数值的间隔更小。
- 指数全为 0 时可表示 0 或次正规数；IEEE 格式中指数全为 1 通常用于 $\pm\infty$ 和 NaN。FP8 E4M3FN 是例外：`FN` 表示仅保留有限数和 NaN，不表示无穷大。

### 1.3. 常用浮点格式速查

|格式|位表示（符号 / 指数 / 尾数）|最大有限绝对值|最小正规格化正数|最小非零正数|AI 中的典型位置|
|---|---|---:|---:|---:|---|
|FP32（binary32）|1 / 8 / 23|$3.4028235\times10^{38}$|$1.1754944\times10^{-38}$|$1.4012985\times10^{-45}$|主权重、累加、数值敏感算子与训练基线|
|FP16（binary16）|1 / 5 / 10|$65504$|$6.1035156\times10^{-5}$|$5.9604645\times10^{-8}$|GPU 训练、推理中的权重和激活|
|BF16|1 / 8 / 7|$3.3895314\times10^{38}$|$1.1754944\times10^{-38}$|$9.1835496\times10^{-41}$|大模型训练、权重与激活；范围接近 FP32|
|TF32*|1 / 8 / 10（计算精度）|与 FP32 相同（正规数范围）|与 FP32 相同|不作为独立存储格式|NVIDIA Tensor Core 上的 FP32 矩阵运算加速|
|FP8 E4M3FN|1 / 4 / 3|$448$|$1.5625\times10^{-2}$|$1.953125\times10^{-3}$|前向激活与权重；精度优先|
|FP8 E5M2|1 / 5 / 2|$57344$|$6.1035156\times10^{-5}$|$1.5258789\times10^{-5}$|梯度或动态范围更大的张量|

\* TF32 是计算模式而非通用存储类型：Tensor Core 读取 FP32 输入时，以 FP32 的指数范围和约 FP16 的尾数精度计算，结果仍按 FP32 输出；不应将其视为可独立保存的 19-bit 张量格式。

> [!note] FP16、BF16 与 FP8 的取舍
> FP16 的尾数比 BF16 多，单位区间附近更精细，但动态范围小得多；BF16 因指数位与 FP32 相同，训练时更不容易上溢/下溢。FP8 的位宽更低，通常必须配合张量级或块级 scale 才能覆盖实际数据分布。

### 1.4. 整数与低比特编码

有符号整数通常采用二进制补码，范围为 $[-2^{n-1}, 2^{n-1}-1]$；无符号整数范围为 $[0, 2^n-1]$。

|格式|位宽|表示方式|编码最小值|编码最大值|AI 中的典型位置|
|---|---:|---|---:|---:|---|
|INT32|32 bit|有符号补码|$-2,147,483,648$|$2,147,483,647$|INT8 / INT4 矩阵乘法的累加器|
|INT16|16 bit|有符号补码|$-32,768$|$32,767$|音频、部分中间结果与特定硬件算子|
|INT8|8 bit|有符号补码|$-128$|$127$|量化权重、激活与推理算子|
|UINT8|8 bit|无符号二进制|$0$|$255$|图像输入、非负张量、非对称量化编码|
|INT4|4 bit|有符号补码，通常两值打包为 1 byte|$-8$|$7$|4-bit 权重量化|
|INT3|3 bit|有符号补码或自定义编码|$-4$|$3$|极限压缩权重，硬件/框架支持较少|
|INT2|2 bit|有符号补码|$-2$|$1$|研究型或极限压缩场景|

> [!warning] INT4 / INT3 不是统一的独立张量类型
> 低比特权重常以 packed bits 方式存储，计算时由专用 kernel 解包，或先反量化到 FP16 / BF16。具体内存占用还要计入 scale、zero-point 和分组元数据。

### 1.5. 量化表示：从编码范围到真实数值

量化并非仅仅把数据转换成 INT8 / INT4。量化后的整数 $q$ 需要与量化参数共同解释，常见关系为：

$$
x \approx s \times (q - z)
$$

- $x$：原始浮点值
- $q$：量化后的整数值
- $s$（scale）：缩放因子，决定一个整数步长代表的真实数值范围
- $z$（zero-point）：零点；对称量化通常取 $z = 0$，非对称量化会保存该值

若 $q$ 为 INT8，其编码范围是 $[-128,127]$；在对称量化中，常把浮点张量的最大绝对值映射到 $127$，即 $s = \max|x|/127$。因此，反量化后的近似范围为 $[-128s,127s]$，而不是固定的 $[-128,127]$。

因此，量化方案需要同时明确：**位宽、量化粒度、量化参数精度与存储位置**。

|设计项|可选项|影响|
|---|---|---|
|位宽|INT8、INT4、INT3、INT2|位宽越低，显存与带宽占用越小，量化误差通常越大|
|量化粒度|per-tensor、per-channel、per-group|粒度越细，精度通常越好，但需要保存更多量化参数|
|量化方式|对称 / 非对称|对称量化实现简洁；非对称量化可更贴合偏移分布|
|量化对象|权重、激活、KV Cache|决定压缩收益、精度风险与算子支持要求|

### 1.6. 非均匀与块量化格式

|格式 / 家族|表示方式|最大 / 最小值如何确定|常见用途|
|---|---|---|---|
|NF4|4-bit 非均匀码本，码点在标准正态分布下更密集|没有固定的全局最大/最小；码本值需乘以每个 block 的 absmax / scale|QLoRA 等 4-bit 微调与权重存储|
|FP8 + scaling|FP8 数值 + 每张量或每块 scale|FP8 本身的范围固定；scale 把真实数据缩放进该范围|训练与高性能推理|
|GGUF / GPTQ / AWQ 的 4-bit 家族|packed 低比特整数 + group scale（部分带 zero-point）|由量化类型、group size 与各组量化参数决定|本地 LLM 推理|

这类格式不能只写成“INT4”：同为 4 bit，码本、分组大小、scale 精度和是否保留离群值都会显著影响精度、显存与吞吐。

### 1.7. 推理阶段的格式组合（待选型）

|组件|保守方案|常见压缩方案|待确认问题|
|---|---|---|---|
|模型权重|FP16 / BF16|INT8、INT4、NF4|目标显存、可接受精度损失、框架支持|
|激活值|FP16 / BF16|INT8（部分方案）|是否需要量化校准、是否出现精度退化|
|KV Cache|FP16 / BF16|INT8、FP8（视硬件而定）|上下文长度、吞吐与长文本质量|
|累加与输出|FP16、FP32|通常保持较高精度|数值稳定性与硬件算子约束|

## 2. 什么是量化？
---
把高精度数据映射为低精度表示，这就叫量化

不妨先以一些数值建立基本认知

|模型|FP16大小|INT4大小（约）|
|---|--:|--:|
|7B|14 GB|3.5 GB|
|13B|26 GB|6.5 GB|
|70B|140 GB|35 GB|

模型7B表示7 billion的参数（每个参数占据的字节数由数制决定）
若为INT8则一个参数为1字节（1B），那么INT8需要7GB的内存空间

### 2.1. 反量化

因为更低精度的INT4数值是无法直接用于计算的，所以需要将其反量化到高精度数值才能进行矩阵乘法。那么就需要保存量化常数

- 量化常数通常是更高数值的例如FP32等

双量化（Double Quantization） 就是：对这些量化常数再做一次量化

## 3. 量化技术
---

量化和训练，可以分为两种。
- Quantization-Aware Training(训练时量化)
- Post-Training Quantization (训练后量化，主流)
	- AWQ


### 3.1. AWQ

AWQ（Activation-aware Weight Quantization）
是Song Han课题组于2023年提出的一种Post-Training Quantization算法，也是目前应用最广泛的4-bit量化方法之一

- 只量化非重要权重、且量化到low-bit，对于salient（重要的/显著的）权重仍使用FP16表示
- 量化后，无需进行后训练
- 激活函数仍为 FP16/BF16
- Activation-aware per-channel Scaling
